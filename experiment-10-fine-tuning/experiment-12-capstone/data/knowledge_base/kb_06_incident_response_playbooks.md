# Enterprise Incident Response Lifecycle & NIST SP 800-61 Standards

## Overview
The Incident Response (IR) framework follows the NIST SP 800-61 framework comprising four main phases: Preparation, Detection & Analysis, Containment Eradication & Recovery, and Post-Incident Activity (Lessons Learned). Structured execution ensures rapid mitigation while preserving forensic chain of custody.

## Key Incident Response Phases
1. **Preparation:** Maintain hardened baselines, updated network diagrams, centralized SIEM logging, and trained incident response personnel.
2. **Detection & Analysis:** Triage incoming alerts, correlate multi-vector indicators, establish scope of compromise, and determine incident severity level.
3. **Containment, Eradication & Recovery:**
   - *Short-Term Containment:* Network isolation, IP perimeter blocking, credential revocation.
   - *Eradication:* Malware removal, vulnerability patching, web shell deletion.
   - *Recovery:* Rebuilding systems from trusted media, restoring data from verified backups, re-enabling monitoring.
4. **Post-Incident Activity:** Document incident timelines, record root cause findings, update detection signatures, and implement preventive controls.

## Grounding & Safety Verification Rule
All incident response recommendations generated by autonomous tools or security assistants MUST be strictly defensive. Defensive recommendations prioritize host containment, account protection, patching, perimeter blocking, and telemetry collection without executing offensive counter-attacks or external scanning.

## MITRE ATT&CK Mapping
- Defensive Framework Alignment: NIST SP 800-61 Rev 2
- MITRE D3FEND Framework Mapping: Network Isolation, Credential Revocation, Process Termination, File Removal
